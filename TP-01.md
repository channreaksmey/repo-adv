## Introduction

We discussed why code quality matters in real-world software development not just for machines to execute, but for humans to read, understand, and maintain. The session covered three core topics: Clean Code principles, PEP8 style guidelines, and Debugging techniques. 

## Clean Code, PEP 8 and Debugging
### Clean Code
Clean Code is code that is easy to read, easy to understand, and easy to change.

Why it matters:
* Code is read far more often than it is written.
* Clean code reduces bugs and makes maintenance cheaper over the project's lifetime.
* It ensure your teammates or your future self can understand your logic quickly.

Tips:
* Use meaningful variable and function names (e.g., `total_price` instead of `tp` or `x`).
* Keep functions small and focused on a single task.
* Avoid "magic numbers" and use named constants instead.
* Remove dead code and commented-out code rather than leaving it to clutter the file.
* Write comments that explain why, not what.

### PEP8
PEP8 is the official style guide for Python code, defining conventions for layout, naming, and formatting.

Why it matters:
* Consistent style across a codebase makes code predictable and professional.
* Many teams and open-source projects require PEP8 compliance.
* Tools like linters can automatically check PEP8 compliance, saving review time.

Tips:
* Use 4 spaces for indentation (never tabs).
* Limit lines to 79 characters.
* Name functions and variables in `snake_case`, classes in `PascalCase`, and constants in `UPPER_SNAKE_CASE`.
* Surround operators and after commas with spaces: `x = a + b`, not `x=a+b`.
* Use blank lines to separate functions and classes logically.

### Debugging
Debugging is the process of finding and fixing errors in code.

Why it matters:
* Bugs are inevitable so knowing how to hunt them efficiently separates good developers from frustrated ones.
* Systematic debugging is faster than random trial-and-error.

Tips:
* Read the error message carefully, Python's tracebacks point directly to the problem line.
* Use `print()` statements or logging to inspect variable values.
* Use a debugger (e.g., pdb, or your IDE's built-in debugger) to step through code line by line.
* Isolate the problem by comment out sections or test functions individually.
* Rubber-duck it because explaining your code out loud often reveals the flaw.

## Tips and tricks to help ensure your code follows PEP 8

1. Use a linter — install and run tools like flake8, pylint, or pycodestyle to automatically detect violations
2. Auto-format your code — use black or autopep8 to fix most formatting issues automatically
3. Configure your IDE/editor — enable real-time PEP8 checking in VS Code (with the Python extension) or PyCharm, many issues get flagged as you type.
4. Integrate into your workflow — add linting to your pre-commit hooks or CI pipeline so violations are caught before code is merged.
5. Study the guide — read the official PEP8 document at peps.python.org and internalize the conventions over time.
